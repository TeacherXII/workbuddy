## 0. 音频立场（贯穿全文的三条）

| # | 立场 | 反面（本文明令避免） |

# 第一部分 · 音频方向基线（交付 B）

> 精炼版。目标是让后续批次**有依据可引**，不是写一本音频圣经。任何后续批次偏离本章，须在其规格文档中显式标注并说明理由。

## 1.1 听觉定位与情绪

对齐 art-bible §1「大屠杀后的午夜大教堂 —— 寂静、敬畏、被注视的恐惧」：

| 美术情绪维度 | 听觉对偶 | 具体手段 |
| --- | --- | --- |
| **敬畏（Awe）** | 大空间的**远** | 远处滴水、高处气流；早期反射稀疏而晚，暗示体积巨大 |
| **被注视（Being Watched）** | **有人但不出声** | 极低密度的非周期性人为噪声（远处铁器轻碰、布料一响即止）；关键是**间隔不可预测** |
| **凝重（Weight）** | **低频密度** | 持续的次低频床（40–90 Hz，−36 LUFS-S 量级），几乎意识不到，撤掉时立刻空 |
| **稀缺的温暖（Scarce Warmth）** | **烛火是唯一有生命的声音** | 可掐灭光源带极轻的火焰噼啪；掐灭 = 这个声音消失 = 玩法即听觉 |

**动态原则（听觉版「70% 安静的暗」）**：环境床与前景事件之间必须保持 **≥12 dB** 的落差。若环境床太满，落足就不再是"事件"。**留白即呼吸**在音频上是字面意义的：允许长达数十秒没有任何前景声。

## 1.3 Bus 架构

```
Master                      ← 无任何动态处理（见下方说明）
├─ World                    ← ★ ADR-003 的 lowpass + ducking 挂在这一层，不在 Master
│   ├─ Music
│   ├─ Ambience
│   ├─ SFX_World            ← 足音 / 声环 / 机关 / 守卫
│   └─ Voice                ← 守卫警示语（diegetic）；本批为空，预留
└─ SFX_UI                   ← ★ 无任何效果器。存档 / 失败 / 拒绝
```

| Bus | 名称字符串 | 标定电平 | 效果链 | 说明 |
| --- | --- | --- | --- | --- |
| Master | `"Master"` | `0.0 dB` | **无** | 见下「为什么 Master 不挂限制器」 |
| World | `"World"` | 模式驱动（§1.4） | `AudioEffectLowPassFilter` ×1（**12 dB/oct，resonance `0.0`** —— ADR-005 **D-7 / D-8**） | 唯一的世界总控；读档淡入也走这一层（§2.3） |
| Music | `"Music"` | `-8.0 dB` | 无 | 音乐是影子不是存在 |
| Ambience | `"Ambience"` | `0.0 dB` | 无 | 环境床 |
| SFX_World | `"SFX_World"` | `0.0 dB` | 无 | 世界音效 |
| Voice | `"Voice"` | `0.0 dB` | 无 | 预留；VO 侧链 ducking 属 Tier2 |
| SFX_UI | `"SFX_UI"` | `0.0 dB` | **无（强制）** | 见下「为什么 UI 不吃任何效果」 |

> **★ v1.1 回填 · ADR-005 D-7 / D-8（本文 v1.0 未覆盖的两项 `World` LPF 参数）**
> - **D-7 · 斜率 = 12 dB/oct**（`AudioEffectFilter.db = FILTER_12DB`）。理由：暂停态要的是「隔一道门」而不是「砌一堵墙」——24 dB/oct @700 Hz 会把世界床压成毫无可辨内容的闷响，直接摧毁 §3 硬点 5 方案 (c) 的全部意义（**世界仍在，只是退到门后**）。
> - **D-8 · resonance = `0.0`**。Godot `AudioEffectFilter.resonance` **默认 0.5**，会在 cutoff 处产生共振峰；700 Hz 的共振峰听感是**一声持续的中频哨音**，直接踩 art-bible §1 调性禁区。**这是一个「不改就会踩红线」的默认值，必须显式写死。**
>
> 二者只作用于 `World`，**不影响 `SFX_UI`**（`SFX_UI` 效果链恒为空，见下）。此条闭合 ADR-005 未决项 **U-3**（「D-7/D-8 须回写音频规格，升 v1.1」）。

**为什么 `Voice` 挂在 `World` 下**：本项目的 VO 目前只有守卫警示语，是**世界内**的声音——它应当和世界一起被凝神 lowpass、被暂停 ducking。若未来出现非世界内的旁白 / 系统语音，须另开 `Voice_UI` 挂在 `SFX_UI` 同级，**不要**改动本条。

**为什么 Master 不挂限制器 / 压缩器**：本作的美学建立在瞬态与留白上。任何 Master 动态处理都会在最需要"一下"的时刻把它压平，并让安静段落抬起底噪。总和不过载由**资产电平天花板 + bus 标定值的算术**保证，不由处理器兜底。最坏情况核算见 §1.5。

**为什么 `SFX_UI` 不挂任何效果器**：
1. UI 音的滤波（LPF 2.2 k / 900 Hz）与空间感（RT60 ≤ 0.25 s）**全部烘焙进资产**。烘焙的好处是可离线度量、零 CPU、且不会被后续有人调 bus 参数悄悄改掉。
2. 若 UI 也吃 World 的 lowpass，存档界面（World 已 lowpass 到 700 Hz）里的存档音会被**二次滤波**，变成一坨听不清的低频糊。这是 §3 硬点 5 的核心。

## 1.4 世界模式三预设（ADR-003 对齐 + 一处澄清）

`World` bus 有且仅有三个互斥预设，由 `TimeController.mode` 驱动：

| mode | `World` volume | `World` LPF cutoff | 用途 | 依据 |
| --- | --- | --- | --- | --- |
| `FLOWING` | `0.0 dB` | `20500 Hz`（= 旁路） | 常态玩法 | — |
| `FOCUS` | `-3.5 dB` | `1200 Hz` | 凝神 | ADR-003「轻微全局 lowpass + ducking」 |
| `PAUSED` | `-12.0 dB` | `700 Hz` | 暂停 / 存档界面 | 本文 §3 硬点 5 |

> **★ 三个预设共用同一条 LPF，其斜率与 resonance 由 ADR-005 D-7 / D-8 钉死**：**12 dB/oct**、**resonance `0.0`**（详见 §1.3 回填注块）。预设之间**只改 cutoff 与 volume，不改斜率、不改 resonance** —— 否则 `FOCUS`↔`PAUSED` 切换会在滤波器形状上产生第二个变量，120 ms 缓动无法覆盖。

- **不变调**：三个预设都**不动 `pitch_scale`**，与 ADR-003 决策一致（避免光敏 / 眩晕）。
- **不硬切（AUD-V6 ≡ control-manifest §8 V-06）**：模式切换须在 **120 ms** 内缓动到位，禁止瞬时跳变。判据：**任何单帧内 bus 增益变化 ≤ 3 dB**。<br>★ **编号归属**：control-manifest §8 已裁定「`AUD-V6` 是 **V-06「转场缓动，禁硬切」的听觉对偶**，归 V-06 管辖，不另编号」。本文 `AUD-V6` 自 v1.1 起为 **V-06 的同源别名**，保留仅为不破坏既有引用。
- **FOCUS 为什么浅、PAUSED 为什么深**：FOCUS 时**世界仍在流动**，守卫脚步是玩法信息，必须听得见 → duck 只能浅。PAUSED 时**时间冻结**（T-03），世界不再产生任何玩法信息 → 世界应当退场，让注意力完全落在 UI 上。目的不同，参数就必须不同。
- **不会打架**：`mode` 是**单值枚举**，三者互斥。打开暂停菜单必然先退出 FOCUS，不存在"凝神中同时打开存档界面"的状态。所以这不是两套效果叠加，而是**同一条效果链上的三个预设**。

> ### ⚠ 对 ADR-003 的一处**澄清**（非推翻）
> ADR-003 原文：「仅施加轻微**全局** lowpass + ducking」。若"全局"被字面实现为**挂在 `Master`**，则：
> - 存档界面里 UI 音会被 700 Hz lowpass，存档「嗒」的辨识度直接归零；
> - 凝神中任何 UI / 字幕提示音也会被闷掉。
>
> **裁决：ADR-003 的「全局」= 全局于"世界"，实现位置为 `World` group bus，`Master` 保持干净。** ADR-003 的**决策内容**（不变调 / lowpass / ducking / 不全局 pitch_scale）**全部保留不变**，本条只钉死实现位置。建议由主理人决定是否以 **ADR-005「音频总线架构与世界模式预设」** 形式补记（见 §7）。

## 1.5 响度标准

### 1.5.1 目标值

| **整体节目响度** | **−20 LUFS-I** | PC 游戏常规区间 −18～−23；肃穆基调取偏低端 |
| **Master 真峰上限** | **−1.0 dBTP** | 防有损编码 / 重采样的样本间过冲 |
| **环境床** | −30 ～ −27 LUFS-S | |
| **世界 foley 响度锚**（足音，**后续批次交付，此处仅登记**） | **−15.0 LUFS-M** | 一切相对关系以此为基准 |
| **任一 UI 音资产** | **≤ −18.0 LUFS-M** | |
| **前景事件 vs 环境床落差** | **≥ 12 dB** | §1.1 动态原则 |

### 1.5.2 「UI 音永不盖过世界音」的量化表述

> **AUD-L1（硬约束）**：`MaxM(任一 SFX_UI 资产) ≤ MaxM(世界 foley 响度锚) − 3.0 dB`

当前取值：世界锚 −15.0 → UI 天花板 **−18.0 LUFS-M**。该关系**烘焙在资产电平里**，不靠 bus 衰减实现——bus 标定值人人可改，资产电平进得了 CI。

### 1.5.3 度量口径（★ 必须统一，否则一切数字失效）

- **响度 = Max-M**（最大瞬时响度，ITU-R BS.1770-4 / EBU R128，**400 ms 滑动窗**），**不是** Integrated。短瞬态资产的 Integrated 无意义。
- 被测文件须在**首尾各补 ≥400 ms 数字静音**，否则窗口无法落位，读数不可复现。
- **真峰 = True Peak（≥4× 过采样）**，不是 sample peak。
- 度量在**资产层**进行（渲染完成、进引擎之前），**不含**任何 bus 增益。

### 1.5.4 波峰因数预算（★ 本文最重要的工程校正之一）

短瞬态资产的「响度目标」与「真峰上限」**不能各自拍脑袋定**——两者一旦冲突，资产在物理上无法交付。

设事件时长 `D` ms，则 400 ms 窗的能量摊薄修正
`W = 10·log₁₀(400 / D)` dB，事件内 RMS ≈ `MaxM + W`，于是

> **可用波峰因数 `CF_max = TP上限 − (MaxM + W)`**

| 资产 | D | W | MaxM | TP 上限 | **可用 CF** | 判定 |
| --- | --- | --- | --- | --- | --- | --- |
| `sfx_ui_save_success` | 110 ms | +5.6 dB | −18.0 | −3.0 dBTP | **9.4 dB** | 8 ms 起音的敲击声典型 CF 9–11 dB → **勉强可交付，须控起音** |
| `sfx_ui_save_failure` | 220 ms | +2.6 dB | −20.0 | −4.0 dBTP | **13.4 dB** | 宽裕 |
| （草图原值对照） | 110 ms | +5.6 dB | −18.0 | **−6.0 dBTP** | **6.4 dB** | ❌ **物理上不可交付** —— 见 §4 修改 M-3 |

**结论**：草图的「−18 LUFS-M ＋ −6 dBTP」对 110 ms 瞬态是一对**互斥**的数字。要么把瞬态压扁到 CF 6.4 dB（那就不再是同一段落要求的「一次敲击，一个瞬态」），要么响度掉 5 dB。本文取**放宽真峰**（见 §4）。

## 2.1 `sfx_ui_save_success` —— 存档成立音「嗒」

**服务事件**：存档成功（0 dB）· 删除成功（−1 dB）

> **⚠ 资产状态（v1.1）**：当前交付物为 **designed v1 —— 程序化合成（分层，非录制/库拉取）**，即下表**路径 B**，**不是** path-A 实录 Foley。它已通过 AUD-P1 / AUD-S1 / AUD-H1 全部资产层断言（实测见 §2.1.2、§3 硬点 1），**但仍是「合成出来的石头」而不是「录来的石头」**。**path A 仍是首选终态**，待真实 Foley 录制后须整体替换并**重跑全部度量**。本节的规格**不因 designed v1 达标而降级**。

### 2.1.1 音色意象与制作路径

> **意象**：石室里，一枚小石子落在石板上；或一道厚木门闩滑进卡槽。**一次接触，一个瞬态，没有余韵。**

这不是形容词，是可执行的制作路径。**优先采样，合成兜底**：

| 路径 | 做法 |
| --- | --- |
| **A · 采样（首选）** | 干燥房间内录制：① 3–5 cm 卵石**落在**石板上（非投掷，非滚动）；② 硬木块**侧面**轻碰厚木板。近距（20–30 cm）小振膜话筒 + 一支 30 cm 外的话筒取一点点房间。取**接触瞬间 + 之后 100 ms**，其余全切。 |
| **B · 分层合成（兜底 / 补强）** | **三层叠加**：<br>① **接触层**（瞬态本体）：短噪声脉冲，带通 **400–900 Hz**，长度 8–15 ms；<br>② **体层**（分量）：正弦 / 三角波 **128 Hz**，指数衰减；<br>③ **质感层**（可选，极低）：砂砾粒子噪声，带通 600–1200 Hz，长度 ≤25 ms，电平比接触层低 12 dB。<br>**禁止**第四层"亮片"。 |

> **★ 关键修正：不要把"基频"当成"全部能量"。** 草图只给了 110–140 Hz 的基频。若资产的能量真的全部集中在那里，这个音在**笔记本扬声器上等于不存在**（典型笔电扬声器在 150 Hz 已衰减 20 dB 以上）。真实的石–石接触声本来就是**宽带瞬态**，其可辨识度来自 **400–900 Hz 的接触带**，而不是低频体。低频体负责"重量"，接触带负责"存在"。二者缺一不可。详见 §4 修改 **M-1**。

### 2.1.2 频谱

| 项 | 规格 |
| --- | --- |
| **低频体基频** | **128 Hz**（标称；容差 110–140 Hz，沿用草图区间） |
| **★ 接触带（新增强制项）** | **400–900 Hz** 必须承载可辨识的瞬态内容 |
| **HPF** | **60 Hz**，12 dB/oct（防浑浊，沿用草图） |
| **LPF** | **2.2 kHz**，**24 dB/oct**（草图未给斜率；24 dB/oct 才能兼顾"去叮"与 AUD-P1） |
| **AUD-P1 复核** | 4 kHz 以上各 1/3 倍频程带 ≤ 峰值带 −30 dB。24 dB/oct @2.2 k 在 4.4 kHz 已 −24 dB、8.8 kHz −48 dB ✅<br>**★ designed v1 实测（v1.1）：−47.1 dB**（最差带 = 4 kHz 带；峰值带 = 125 Hz 带）→ 余量 **17.1 dB**，**pass** |
| **★ 小扬声器存活约束（AUD-S1）** | `MaxM(原始) − MaxM(250 Hz / 12 dB-oct 高通后)` **≤ 6.0 dB**（目标 ≤4.0）<br>**★ designed v1 实测（v1.1）：3.65 dB**（−20.67 → −24.32 LUFS）→ **pass，且达成「目标 ≤4.0」** |

> **AUD-S1 是什么**：把资产做一次 250 Hz 高通（模拟没有低频的小扬声器），再量一次响度。差值 ≤6 dB 意味着**至少约 25% 的能量在 250 Hz 以上**，即这个音在笔电 / 小音箱 / 手机外放上仍然存在、仍然可辨。这是本文把"能不能听见"变成断言的方式。

### 2.1.3 时长与包络（ADSR）

| 段 | 值 | 说明 |
| --- | --- | --- |
| **Attack** | **8 ms**（标称；上限 8 ms，下限 5 ms） | **不要更快**。< 5 ms 会把波峰因数推过 §1.5.4 的 9.4 dB 预算，导致必须降响度 |
| **Decay** | **100 ms**（容差 80–120 ms），指数型 | |
| **Sustain** | **0**（无） | 有 sustain 就成了"音"而不是"响"（沿用草图） |
| **Release** | 折入 Decay | |
| **总长** | **110 ms**（容差 90–140 ms），末样本落零交叉 | 128 Hz 周期 7.8 ms → 110 ms ≈ 14 周期，足以建立"分量"感 |
| **★ 收尾窗（F-6，v1.1 固化）** | **升余弦（raised-cosine）淡出**，且**首末样本严格 = 0** | 见下 |

> ### ★ F-6 · 升余弦淡出 + 零交叉 —— **已采用的设计决策**（v1.1 由「制作建议」升格为决策）
>
> **决策**：所有 UI 音资产的收尾**必须**使用**升余弦淡出窗**（而非线性淡出），并保证**首样本与末样本严格为 0**。
>
> **为什么线性淡出不够**：线性窗在**淡出起点处斜率不连续**（一阶导数突变）。对 110 ms 这种极短瞬态，这个拐点会产生一个宽带的低幅畸变——**它本身就是一次明亮成分**，与 §1.2 红线、AUD-P1 直接对立。升余弦窗的一阶导数在两端均为 0，**不引入任何新的高频**。
>
> **为什么零交叉是硬要求**：末样本若不为 0，播放结束即产生**直流跳变** = 一次全频带咔嗒（§1.6 已写明）。这是 F-6 在 designed v1 制作中**实际踩到并修复**的问题。
>
> **实测确认（本棒现场复测）**：`sfx_ui_save_success` 首/末样本 = **0 / 0**；`sfx_ui_save_failure` 首/末样本 = **0 / 0**。两资产 AUD-P1 分别 −47.1 / −80.7 dB，**远优于 −30 dB 阈值** —— 这正是升余弦收尾未引入高频畸变的证据。
>
> **适用范围**：本决策**不限于本批两个资产**，适用于**所有** `SFX_UI` 资产（含 §2.4 的 `sfx_ui_focus_move` Tier2 存根）。与 §2.5.3「偷声必须 20 ms 淡出」是同一条物理原理的两个应用面（资产层 / 运行时层）。

| 项 | 值 |
| --- | --- |
| **MaxM** | **−18.0 LUFS ±0.3** |
| **True Peak** | **≤ −3.0 dBTP** ← 草图为 −6，见 §4 修改 **M-3** |

### 2.1.5 声像与空间

| 项 | 规格 |
| --- | --- |
| **声道** | **单声道**源文件 |
| **播放节点** | `AudioStreamPlayer`（**非** `AudioStreamPlayer3D`），`mix_target = STEREO` → 幻象居中 |
| **距离衰减** | **无**（非世界内声源） |
| **混响** | **RT60 ≤ 0.25 s，且必须烘焙进资产**，不走任何 reverb send（§1.3）。取"贴石室"而非"大厅"：早期反射密集、晚期混响几乎没有 |
| **单声下混** | 单声道源天然安全 ✅ AUD-A1 |

### 2.1.6 为什么这样做

- **支柱三 · 自主掌控**：存档是玩家**主动**冻结自己进度的行为。声音的任务是给这个决定一个**落点**——像把一枚棋子按在棋盘上。落点是触觉的，不是嘉奖的。
- **风险 2 缓解（概念 §7）**：「反馈走物理 / 触觉而非庆祝 / 闪亮」。石落石板是纯物理事件，它在语义上**无法**被听成庆祝。
- **art-bible §1 红线**：LPF 2.2 kHz + AUD-P1 从物理上封死了"亮"的可能。**这个音不可能被误做成一个提示音。**
- **与足音同族但更低**（草图意图）：同为石–木接触 foley，但低频体更沉（128 Hz vs 足音的中频重心）、更干（无 surface 变体、无空间）。且二者**时间上永不共存**——存档界面处于 T-03 冻结态，玩法足音不可能触发，混淆风险为零。

### 2.1.7 关于「删除成功 = −1 dB」

**确认草图，但须说清它不是什么**：−1 dB **低于响度可辨阈（≈1 dB）**，因此它**不是一个辨识通道**。删除与存档的区分完全由**字幕**（"已删除 · 槽 N" vs "已存档 · 槽 N"）与**视觉**（行转空态 vs 行刷新）承担，音频只负责"这一下成立了"。

那 −1 dB 的意义是什么？**混音姿态**：删除是一次销毁，一次销毁不该和一次保全一样理直气壮。这 1 dB 玩家听不出来，但它让混音表在语义上是自洽的。

> **⚠ 资产状态（v1.1）**：同 §2.1 —— 当前交付物为 **designed v1 程序化合成**（下表**路径 B**），**非** path-A 实录 Foley。已通过全部资产层断言（实测见 §2.2.2、§3 硬点 1），**待真实 Foley 录制后替换并复测**。

### 2.2.1 音色意象与制作路径

> **意象**：厚门顶到门框、**没能合上**；石板下沉一寸、**卡住**。表达的是「动作没走完」，不是「你错了」。

| 路径 | 做法 |
| --- | --- |
| **A · 采样（首选）** | 厚木门推到最后一寸被挡住的那一下；或一块重石板落到位但被垫住。要的是**闷、短促的受阻**，不是撞击。 |
| **B · 分层合成** | ① **体层**：正弦 **80 Hz**，稍软起音；② **阻塞层**：低通噪声（LPF 600 Hz）+ 极轻的低频摩擦，模拟"卡住"的粗糙感；③ 全体过 LPF 900 Hz。 |

### 2.2.2 频谱

| 项 | 规格 |
| --- | --- |
| **基频** | **80 Hz**（容差 70–90 Hz，沿用草图） |
| **★ LPF** | **900 Hz**，24 dB/oct —— **这一项就是「闷」的本体**（草图原判，完全采纳） |
| **HPF** | **45 Hz**，12 dB/oct（沿用草图） |
| **★ 小扬声器存活约束（AUD-S1-F）** | `MaxM(原始) − MaxM(HPF 250 Hz)` **≤ 8.0 dB**（比成功音宽 2 dB —— "闷"本来就意味着能量偏低频，但**不能偏到消失**）<br>**★ designed v1 实测（v1.1）：4.53 dB**（−24.82 → −29.35 LUFS）→ **pass，余量 3.47 dB**。★ 注意它甚至优于成功音的 6.0 dB 阈 —— 说明 §2.2.2 的 250–900 Hz 谐波内容确实建起来了，AR-2 担心的"闷到消失"**未发生** |
| **AUD-P1 复核（v1.1 新增行）** | 4 kHz 以上各 1/3 倍频程带 ≤ 峰值带 −30 dB。LPF 900 Hz / 24 dB/oct 使 4 kHz 已在 −50 dB 量级 ✅<br>**★ designed v1 实测：−80.7 dB**（最差带 = 20 kHz 带；峰值带 = 80 Hz 带）→ 余量 **50.7 dB**，**pass**。失败音比成功音再低 33.6 dB，符合"更闷"的设计意图 |

> **为什么失败音也必须过 AUD-S1**：LUFS-M 是全带 K 加权度量，**不模拟小扬声器的低频衰减**。两个 MaxM 相同的音，在笔电上可以相差 15 dB 以上。如果只管住"失败不比成功响"而不管"失败在小扬声器上还听得见"，就会从一个坑掉进对面那个坑——**失败音变成沉默，直接违背立场 3**。80 Hz 基频的谐波（160 / 240 / 320 / … / 880 Hz）在 900 Hz LPF 下全部保留，250–900 Hz 有足够内容，AUD-S1-F 可达成。

| **Attack** | **12 ms**（上限 12 ms）—— 略软的起音 = 闷（沿用草图） |

### 2.2.7 为什么这样做

- **立场 3**：失败音的全部工作是让玩家知道"这一下没落地"，然后**闭嘴**。它不解释、不指责、不加重。解释归字幕（"存档失败 · 磁盘写入未完成"），加重归视觉（⚠ 三角 + 2 Hz 双拍）。
- **三通道分工**：音（未成立）+ 字幕（为什么）+ 视觉（在哪儿、持续多久）。**音频承担的信息量最小**，这正是 AUD-A2 / C-05 的要求。
- **为什么"闷"而不是"尖"**：尖 = 警报 = 危险 = 玩法语义。存档失败**不是危险**，它是一次没成立的操作。把它做成警报会污染真正的警报语汇（守卫发现），那才是灾难。

### 2.2.8 ★ `action_denied` 是别名，不是资产（工程关键）

`save_slots_screen.gd` L48 的注释写着 `# same thud, -3dB`，L285 又传了 `-3.0`。**若音频层把 `action_denied` 注册为"一个已经渲染低 3 dB 的独立资产"，运行时结果是 −6 dB，静静地翻倍衰减。**

> **AUD-G1（单一衰减来源铁律）**：cue 表中每一项的 `base_gain_db` **恒为 `0.0`**。所有相对电平**只能**由调用方的 `gain_db` 参数表达。

cue 解析表：

| cue 名 | 解析到的 stream | `base_gain_db` |
| --- | --- | --- |
| `save_success` | `sfx_ui_save_success.wav` | **0.0** |
| `save_failure` | `sfx_ui_save_failure.wav` | **0.0** |
| `action_denied` | **`sfx_ui_save_failure.wav`（同一个 stream）** | **0.0** |

**为什么保留 `action_denied` 这个名字**：`tests/unit/test_save_ui.gd` L901 断言的是 **cue 名**。名字承载**语义**（供日志、QA、字幕联动），stream 承载**音色**，二者是**多对一**且这是故意的。

**为什么铁律必须存在**：现有单测只看得见调用方参数（L902 `assert_lt(gain_db, 0.0)`），**看不见 cue 表**。一个藏在 cue 表里的额外 −3 dB 对 CI 完全隐形，只会在某次有人戴耳机试玩时被"感觉有点小"地发现，然后被错误地整体调响。

## 2.3 读档成功 —— 0.4 s 视听同源淡入（**无 UI 音**）

### 2.3.1 时间轴

| t | 视觉 | 音频 |
| --- | --- | --- |
| `t = 0` | `SCR_SLOTS` + scrim **瞬间卸载**；`_fade` 遮罩 alpha = 1（全黑） | `World` bus 电平**立即**打到 `−60 dB`（地板）；`SFX_World` **静音**；`World` LPF 直接置 `20500`（旁路）；世界模式锁定 `FLOWING` |
| `0 < t < 0.4` | `_fade` alpha = `1 − world_fade_alpha()` | `World` 电平 = `linear_to_db(world_fade_alpha())`，**同帧、同一个值** |
| `t = 0.4` | 遮罩隐藏，屏幕完全是世界 | `World` 电平**吸附**到 `0.0 dB`；`SFX_World` 解除静音；玩法音允许触发 |
| `t = 0.4` | 字幕「已读取存档 · 槽 N」 | —（字幕在淡入完成才发，沿用草图；黑屏中的字幕会悬空） |

### 2.3.2 ★ 淡入载体：`World` bus，不是 `Ambience` bus（对草图的修改）

草图写「Ambience bus 从 −∞ 升起」。**本文改为 `World` group bus**，理由三条：

1. **Music 也属于"世界重新出现"。** 只抬 Ambience 会让音乐在 t=0 就以全电平硬切进场，而画面还是全黑——正是草图自己要避免的"先听到后看到"，只是换了个通道。
2. **顺序问题一次解决。** 淡入必须发生在 `FLOWING` 预设下（否则玩家淡入回来的是一个被 ducking + 700 Hz lowpass 过的世界）。把淡入放在 `World` 上，就可以在 t=0「先打地板、再切预设」——因为一切都在 −60 dB，切预设不可能被听见。若淡入在 `Ambience` 上，`World` 从 `PAUSED(−12/700 Hz)` 切到 `FLOWING(0/20500)` 这一步必然在可闻电平上发生，会产生一次"揭盖"感。
3. **`World` 的标定值本来就是 0.0 dB**（§1.3），淡入终点与模式常态天然重合，不会出现"淡入到一个和常态不同的值"的分叉。

> 草图的**意图**（世界的声音沿视觉同一条曲线回来）**完全保留**；改的只是这条曲线挂在哪根总线上，且改后更完整地实现了该意图。

### 2.3.3 ★ 曲线映射：alpha → 振幅，不是 alpha → dB

> **AUD-F1**：`World.volume_db = linear_to_db( max(a, 0.001) )`，其中 `a = SaveSlotsScreen.world_fade_alpha()`。地板 `−60 dB`。

**为什么是振幅线性，不是 dB 线性**：

- `volume_db = lerp(-60, 0, a)`（dB 线性）在 a=0.5 时是 **−30 dB**——几乎听不见。整条淡入会表现为"前 80% 无声、最后 20% 突然出现"。
- alpha 合成在物理上就是**把世界的辐射亮度乘以 a**；音量的振幅缩放在物理上就是**把声压乘以 a**。**两者是同一个数学操作作用在两种信号上**——这是"视听同源"最字面、也最不需要心理声学辩护的映射。

`world_fade_alpha()` 已经是 `ease(fade_progress(), 0.5)`，在 Godot 中即 `1 − (1−s)²` = **ease-out**（符合 V-06 与草图 §3.3）。音频**不得**再叠加第二条曲线。

### 2.3.4 ★ 同源实现约束（硬点 3 的落地）

| # | 约束 | 说明 |
| --- | --- | --- |
| **AUD-F2** | **音频侧禁止创建任何 `Tween` / 计时器 / 插值器。** | 唯一驱动源是 `SaveSlotsScreen.tick(real_delta)` |
| **AUD-F3** | **谁驱动谁**：`SaveUiModel._fade_t`（唯一时钟，墙钟 delta，不吃 `Engine.time_scale`）→ `world_fade_alpha()`（唯一曲线）→ **同一帧内**同时喂给 `_set_alpha(_fade, 1−a)` 与 `AudioDirector.set_load_fade(a)` | 视觉与音频读**同一个函数的同一次返回值** |
| **AUD-F4** | **驱动偏差 = 0 帧**（强制）。若工程侧确实无法同帧（例如音频在 `_physics_process` 读），上限 **1 帧 @60 fps = 16.7 ms，且只能是音频滞后** | |
| **AUD-F5** | **端到端 A/V 偏移容差**：音频**滞后**视频 ≤ **40 ms** 可接受；音频**超前** **0 ms 容忍** | 依据：音频超前的可察觉阈约 45 ms，远低于滞后的约 125 ms；且物理直觉本就是"光先到、声后到" |
| **AUD-F6** | `begin_load_fade()` **必须在 t=0 当帧就把 `World` 打到地板**，不得等第一次 `set_load_fade()` | 否则第 0 帧会以全电平渲染一个音频缓冲 = 一声爆音（且是明亮瞬态 = 踩红线） |
| **AUD-F7** | `end_load_fade()` 必须把 `World` **吸附**到 `0.0 dB` | 现有代码在最后一 tick 会跳过 `_set_alpha`（`_fade.visible` 已为 false），音频侧最后收到的 `a` 可能是 0.97 左右，残留 −0.26 dB。吸附幅度 < 0.3 dB，不可闻 |
| **AUD-F8** | 淡入期间 `set_world_mode()` 调用**被忽略**并记 warning | 防止暂停菜单的关闭流程在淡入中途把 `World` 抢回 `FLOWING(0 dB)`，一步跳到全响 |

> **★ 结论：一旦采用同源驱动，草图担心的「先听到后看到」在结构上不可能发生。** 唯一的额外延迟来源是音频输出缓冲（Godot `audio/driver/output_latency` 默认 15 ms），而缓冲**只能让音频更晚**，永远不会更早。「先听到后看到」只会在音频跑自己的 tween 且启动点更早（例如挂在 `load_completed` 信号上，而视觉等到下一次 `_process`）时出现——AUD-F2 正是为了封死这条路。

### 2.3.5 玩法音门控

草图要求「足音 / 声环等在 t=0.4 s 后才允许触发」。**采纳，并做双保险**：

1. **总线级**：`SFX_World` 在 `begin_load_fade()` 静音，`end_load_fade()` 解除。
2. **触发级**：读档淡入期间玩法层不得**发起**任何世界音。

为什么两层都要：只做总线静音，则淡入中触发的长音会在 t=0.4 解除静音时"半截出现"；只做触发门控，则淡入前已在飞行中的尾音会穿透。两层叠加后，t=0.4 的解除静音时**没有任何声音在播**，因此不会产生解除静音的咔嗒。

### 2.3.6 为什么读档成功没有 UI 音（硬点 2 的裁决）

> **✅ 确认草图判断。不修正。**

三条理由，从弱到强：

1. **草图的理由成立**：世界重新出现本身就是最强的"成立"反馈。再叠一个 UI「嗒」= 对同一个事件发两次"成立"信号，玩家会下意识去找"这两声分别是什么意思"。
2. **立场 2（世界优先）**：这是全项目唯一一个 UI 事件的结果**就是世界本身**的时刻。在这个时刻让 UI 出声，等于让 UI 在自己该退场的那一秒抢麦。
3. **★ 频谱上根本挤不进去**：t=0 时 `World` 在 −60 dB，一个 −18 LUFS-M 的 UI 音会孤零零地悬在纯粹的静默里，比它在任何其他语境下都要响得多得多（**相对**世界电平高出 40 dB 以上）。要让它不刺耳就必须大幅压低，压低到听不清又失去意义。**这个位置在物理上不适合放任何 UI 音。**

代码侧已经落实：`test_save_ui.gd` L980-981 断言读档成功时 `_cues.size() == 0`。本规格与之一致，无需改动。

### 2.3.7 ⚠ 一个被接受的沉默缺口（诚实记录）

从玩家按下〔读取〕/〔覆盖〕到 `save_completed` / `load_fade_begin` 到达之间（`BUSY_WRITING` / `BUSY_READING`，最长 `BUSY_TIMEOUT_SEC = 3.0 s`），**当前完全无声**。

**裁决：不补"提交音"。** 理由：补一个提交音就等于对一次操作发两声（提交 + 成立），正是 §2.3.6 反对的模式；而"操作是否被受理"已由行徽标〔写入中…〕/〔读取中…〕承担（视觉通道足够）。病理情况（3 s 超时）由失败音兜底。

**登记为观察项**，不是遗漏：若实测中写盘经常 >300 ms 且玩家反馈"按了没反应"，正确的补救是**视觉**（徽标动效）或**缩短超时**，**不是**加音。

## 2.5 触发时机 · 打断 · 叠音规则

### 2.5.1 触发时机（对齐已有状态机，无需新增状态）

全部 cue 由 `SaveSlotsScreen._handle(intent)` 在**意图执行的同一帧**发出（现有代码 L280–313）。音频层**不订阅** `EventBus`，不自行判断状态——**状态机只有一个，在 `SaveUiModel` 里**。

### 2.5.2 重触发阶梯（AUD-R1）

针对连续快速操作（典型：在只读检查点行上按住 `Del`，或在空槽上按住 `Enter`，键盘自动重复会让 `press_*` 每帧触发）：

| 同名 cue 的间隔 | 行为 |
| --- | --- |
| **< 80 ms** | **抑制**（不播、不重启已在播的实例） |
| **80–600 ms** | 播放，但在调用方 `gain_db` 基础上**每次再 −2.0 dB**，**下限 −9.0 dB** |
| **> 600 ms** | 阶梯**复位**到 0 |

**为什么要这条**：
- 不做 → 「哒哒哒」的机关枪感，直接破肃穆基调（这正是 O-5 决定焦点音默认关的理由，同一个病）。
- 做成完全抑制 → 破立场 3（禁用不等于沉默）：玩家第 2 次按下时得到彻底的静默，会以为 UI 卡了。
- **阶梯**是唯一同时满足两边的形态：第一次清晰，之后逐渐退到背景，但**永不为零**（−9 dB 下限），且视觉拒绝提示（`_hint` 标签）始终在。

> **与 AUD-G1 的关系**：AUD-G1 管的是**静态** cue 表（`base_gain_db ≡ 0`）。AUD-R1 是**唯一被允许的动态修正**，且必须实现在音频层（`save_slots_screen.gd` 不得改）、必须可在测试中关闭（`set_retrigger_ladder_enabled(false)`），否则 QA 无法对单次电平做确定性断言。

### 2.5.3 复音与偷声

| 项 | 规格 |
| --- | --- |
| **`SFX_UI` 播放器池** | **3 个** `AudioStreamPlayer` |
| **分配** | 优先取已播完的；全忙则**偷最早开始**的那个 |
| **★ 偷声必须淡出** | 被偷 / 被顶替的实例以 **20 ms 线性淡出**，**禁止硬停** |
| **同时发声上限** | 3（UI）。超出即偷声，不排队 |

> **为什么偷声必须淡出**：硬停一个正在衰减的波形会产生直流跳变，听感是一次**明亮的咔嗒**——那是全频带瞬态，直接违反 AUD-P1 与美术红线。20 ms 足以消除跳变，又短到不会拖累下一声。

### 2.5.4 与暂停 / 淡入的交互

| 情形 | 规则 |
| --- | --- |
| UI cue 与 `PAUSED` ducking 同时 | 无冲突：cue 在 `SFX_UI`，ducking 在 `World`，两条并行支路 |
| UI cue 在读档淡入期间 | **不可能发生**：`load_fade_begin` 之后模型处于 `LOADING_FADE`，`is_input_locked()` 为真，一切输入被吞。若因未来改动仍发生，音频层**照播不误**（不做特殊处理）——静默地吃掉一个 cue 比一个无法解释的沉默更糟 |
| 存档界面关闭时仍有 cue 在播 | **照播完**。cue 的宿主是 `AudioDirector`（自动加载单例），不是屏幕节点；屏幕销毁不得截断声音（§6） |

## 硬点 4 · 与检查点「咔」的区分 —— **四个正交维度**

`save-system.md` §5 L70 已定：检查点 = 低饱和微光环 + 轻「咔」foley，**diegetic，不弹窗**。手动存档音必须与它**同族**（都是石 / 木接触 foley）但**可区分**。

> ### ★ 主区分维度：**空间性 = 能动性**
> **检查点是世界对你做的事**（你没要求它，它自己发生了）→ 声音**在世界里**，有位置、有距离、有房间。
> **手动存档是你对世界做的事**（你主动冻结了自己的进度）→ 声音**在你脑子里**，居中、无距离、无房间。
>
> 这不是随手选的编码——它把**支柱三「自主掌控」**直接映射成了一个听觉物理属性。玩家不需要学习这个区别，它符合直觉。

### 区分矩阵

| # | 维度 | 检查点「咔」（自动） | 手动存档「嗒」 | 是否**足以单独**区分 |
| --- | --- | --- | --- | --- |
| **1** | **空间性**（主） | Diegetic：从检查点体积的世界坐标发声，有距离衰减、有声像、走世界混响 | Non-diegetic：单声道居中、无衰减、无声像、混响烘焙且 RT60 ≤0.25 s | ✅ **是** |
| **2** | **Bus** | `SFX_World` —— 吃凝神 lowpass / 暂停 ducking | `SFX_UI` —— 不吃任何世界处理 | ✅ 是（是维度 1 的实现） |
| **3** | **频谱重心** | 更高更亮：**click**，重心 700–1400 Hz，LPF 4 kHz | 更低更钝：**knock**，重心 300–600 Hz，LPF 2.2 kHz | ✅ 是 |
| **4** | **包络 / 有无"体"** | **没有 body**：40–70 ms，attack ≤3 ms，几乎纯接触 | **有 body**：110 ms，含 100 ms 的 128 Hz 低频衰减 | ✅ 是 |

**一句话**：**「咔」是指甲盖敲石头（有接触无重量），「嗒」是石子落石板（有接触有重量）。** 同一个材质世界，两种不同的物理事件。

## 硬点 5 · 暂停语境下的 bus 行为 —— **裁决：ducking + lowpass，且与 ADR-003 不冲突**

### 问题

存档界面打开时世界被 scrim 遮蔽 60%。世界音继续播、ducking、还是静默？会不会和 ADR-003 的凝神 lowpass / ducking 打架？

### 三个候选

| 方案 | 结果 | 裁定 |
| --- | --- | --- |
| **(a) 原样继续播** | 玩家在菜单里听见守卫走动，制造**虚假的紧迫感**（"我在菜单里但世界还在动？"）。且与 T-03「时间冻结」在语义上直接矛盾 | ❌ |
| **(b) 完全静默** | ① 掉进真空，破坏肃穆的连续性；② 回到游戏时环境床要重新起，凭空多一次转场；③ **★ 绝对静默会让 −18 LUFS-M 的 UI 音显得非常响**——因为响度是相对的，把背景抽空等于把 UI 音抬高 30 dB 的相对量。这会直接破坏立场 1「反馈是质地不是公告」 | ❌ |
| **(c) Ducking + lowpass（"隔一道门"）** | 世界床仍在，但退到门后；UI 音在其上清晰，且**不需要变响**就清晰 | ✅ **采纳** |

### 裁决参数

`World` bus 预设 `PAUSED`：**volume `−12.0 dB`，LPF `700 Hz`**，切换缓动 **120 ms**（AUD-V6）。

### 与 ADR-003 是否打架？—— **不打架，三条理由**

1. **状态互斥，不是效果叠加。** `TimeController.mode` 是**单值枚举** `FLOWING | FOCUS | PAUSED`。打开暂停菜单必然先退出凝神，不存在"FOCUS 与 PAUSED 同时成立"的状态。因此 `−3.5 dB/1200 Hz` 与 `−12 dB/700 Hz` 是**同一条效果链上的两个互斥预设**，永远不会相乘。
2. **目的不同，参数就该不同。** ADR-003 的凝神 duck 服务的是"凝神质感"，而凝神时**世界仍在流动**、守卫脚步仍是玩法信息 → duck 必须**浅**。暂停时世界**不产生任何玩法信息** → 世界应当**退场**。用同一组参数反而是错的。
3. **ADR-003 的决策内容全部保留**：不变调 ✅、仅 lowpass + ducking ✅、关键 `AudioStreamPlayer` 不做全局 `pitch_scale` ✅。本文没有推翻它的任何一条。

### ⚠ 但有一处必须澄清（否则真的会打架）

ADR-003 原文「仅施加轻微**全局** lowpass + ducking」。**若"全局"被实现为挂在 `Master`**：

- 存档界面下 UI 音会被 **700 Hz** lowpass。存档「嗒」的接触带（400–900 Hz）被砍掉大半，失败音（本就 LPF 900 Hz）会变成一坨无法辨认的低频糊。
- **这才是真正的冲突** —— 而且它是**实现位置**造成的，不是**决策内容**造成的。

> **裁决：ADR-003 的「全局」= 全局于"世界"。效果链挂在 `World` group bus，`Master` 保持干净、无任何处理。**

建议主理人决定是否以 **ADR-005** 形式补记（§7 · OOS-4）。

### ⚠ 附带发现：暂停机制本身没被钉死，且它决定音频接线

`control-manifest.md` T-03 写「用显式暂停（`paused` / `time_scale=0`）」—— **两者并列，没有选定**。全仓库 `grep` 结果：**没有任何代码使用 `get_tree().paused` 或 `process_mode`**。而 `save_slots_screen.gd` 用墙钟（`Time.get_ticks_msec()`）驱动 `tick()`，这暗示当前走的是 `time_scale = 0`。

两种机制对音频的要求**完全不同**：

| 暂停机制 | 对音频的后果 |
| --- | --- |
| `Engine.time_scale = 0` | `AudioStreamPlayer` 不受影响，照常播放。音频侧**无需**特殊处理 |
| `get_tree().paused = true` | Godot 会暂停 `PROCESS_MODE_PAUSABLE`（默认）的 `AudioStreamPlayer`。**后果：① 环境床与音乐会停 → 方案 (c) 直接失效；② `SFX_UI` 池会停 → 存档成功音根本播不出来**（因为存档界面只存在于暂停期间！）。必须把 `AudioDirector` 及其全部播放器设为 `PROCESS_MODE_ALWAYS` |

> **工程指令（§6，两种机制下都安全的写法）**：`AudioDirector` 及其 `_ui_pool` / `_ambience` / `_music` 全部设 `PROCESS_MODE_ALWAYS`；世界音效播放器保持默认 `PROCESS_MODE_PAUSABLE`（它们**应该**随世界冻结）。这样无论 T-03 最终选哪个，音频都正确。

| **M-3** | §3.1 / §3.2 响度 | True Peak ≤ **−6 dBTP** | **成功音 ≤ −3.0 dBTP，失败音 ≤ −4.0 dBTP** | ★ **「−18 LUFS-M ＋ −6 dBTP」对 110 ms 瞬态是一对物理上互斥的数字。** 波峰因数预算只剩 6.4 dB，而 8 ms 起音的敲击声典型 CF 为 9–11 dB。要么把瞬态压扁（违背同段落自己要求的「一次敲击，一个瞬态」），要么响度掉 5 dB。完整算式见 §1.5.4。 |
| **M-4** | §3.2 响度 | 失败音 **−18 LUFS-M**（与成功音"同档"） | 失败音 **−20.0 LUFS-M ±0.3** | 原则不变（失败绝不更响），实现方式改。"名义相等"在 ±0.3 dB 测量不确定度下有约 50% 概率实测翻车，门禁会随机红。给 1.0 dB 的确定性余量后，AUD-H1 变成一条**永远可通过**的断言；且 2 dB 差仅略高于可辨阈，仍属"同档"。详见 §3 硬点 1。 |
| **M-5** | §3.2 音高包络 | 「120 ms 内下滑 2 个半音」 | **采纳 2 半音 / 120 ms，新增上限 AUD-P2：绝不超过 3 个半音** | 草图值正确，但缺上限。>3 半音会滑进"失败长号"的滑稽/嘲弄语汇，同时踩碎肃穆基调与立场 3。上限的作用是防止后续迭代中有人"觉得不够明显"而一路加大——不够明显时该加的是中频内容，不是下滑量。 |
| **M-6** | §3.3 淡入载体 | 「**Ambience** bus 从 −∞ 升起」 | **`World` group bus**（Music + Ambience + SFX_World + Voice 的父线） | 意图完全保留，载体上移一层。① 只抬 Ambience 会让 Music 在 t=0 全电平硬切进场——正是草图要避免的错位，只是换了通道；② `World` 从 `PAUSED(−12/700 Hz)` 切回 `FLOWING` 这一步若在可闻电平上发生会产生"揭盖"感，把淡入放在 `World` 上就能"先打地板再切预设"，一次解决顺序问题。详见 §2.3.2。 |
| **M-7** | §3.3 曲线 | 「沿同一条 ease-out 曲线升至标定值」（未定义 alpha→电平的映射） | **`volume_db = linear_to_db(a)`**（振幅线性），地板 −60 dB | 草图定了曲线但没定映射，而映射选错会让"同一条曲线"听起来完全不同步：`lerp(-60, 0, a)` 在 a=0.5 时是 −30 dB（几乎无声），整条淡入会表现为"前 80% 无声、最后 20% 突然出现"。alpha 合成 = 亮度乘以 a，音量缩放 = 声压乘以 a，**同一个乘法**——这是最字面的"同源"。 |

## 5.3 节点挂点

**新增自动加载单例 `AudioDirector`**（`res://src/core/audio_director.gd`），子节点：

| 节点 | 数量 | Bus | `process_mode` |
| --- | --- | --- | --- |
| `AudioDirector`（根） | 1 | — | **`PROCESS_MODE_ALWAYS`** |

**为什么必须是自动加载单例，不能挂在存档界面上**：
1. `_end_load_fade()` 会把屏幕 `visible = false` 并关闭；若 cue 的宿主是屏幕节点，正在播的声音会被截断。
2. 0.4 s 淡入在 t=0.4 结束时屏幕已退场，而音频需要在那之后仍能吸附电平。
3. 既是 L5 UI 又是 L4 玩法的共同下游，任何一方拥有它都是错误的耦合。

**为什么 `PROCESS_MODE_ALWAYS` 是硬要求**：见 §3 硬点 5 的附带发现。若 T-03 最终选 `get_tree().paused = true`，默认 `PAUSABLE` 会让**存档成功音根本播不出来**（存档界面只存在于暂停期间）。设为 `ALWAYS` 在两种暂停机制下都正确。

> **零新增事件声明**：`AudioDirector` **不声明任何 signal**，**不向 `EventBus` 添加任何词汇**。它只**订阅**既有的 `time_scale_changed(old, new, mode)`，其余全部走直接方法调用 / 注入 Callable。**不触及 E01-S9 冻结。**

## 5.6 0.4 s 淡入的 tween 驱动接口约定

**这是本批唯一需要改动 `save_slots_screen.gd` 的地方**（作者不改，转派程基岩）。

**为什么必须改屏幕、不能让音频自己算**：音频若订阅 `load_completed` 自跑 0.4 s 计时器，就是**两个独立时间源**，正是草图 §3.3 明令禁止的「先听到后看到」的成因（AUD-F2）。

**沿用该文件既有架构**（L24 注释：「Everything that would traditionally be an outgoing event is delivered through an injected Callable instead」），**新增第 4 个 sink**，而不是直接引用 `AudioDirector`——这样屏幕在没有音频单例的情况下仍可 headless 测试：

```gdscript
## fade_sink(phase: String, alpha: float)
##   phase ∈ "begin" | "tick" | "end"
var _fade_sink: Callable = Callable()

func set_fade_sink(sink: Callable) -> void:
	_fade_sink = sink
```

**四个插入点**（行号基于当前合入版）：

| 位置 | 现有代码 | 插入 |
| --- | --- | --- |
| ~L151，`set_audio_sink()` 之后 | — | `set_fade_sink()` 定义 |
| **L742 `_begin_load_fade()`**，`_set_alpha(_fade, 1.0)` 之后 | `_fade.visible = true` … | `_fade_sink.call("begin", 0.0)` |
| **L788–789 `tick()`**，与 `_set_alpha(_fade, 1.0 - world_fade_alpha())` **同一个 `if` 块内、同一帧** | `if before == LOADING_FADE and _fade != null and _fade.visible:` | `var a := world_fade_alpha()`；`_set_alpha(_fade, 1.0 - a)`；`_fade_sink.call("tick", a)` ← **★ 必须读同一个 `a`，不得各调一次 `world_fade_alpha()`** |
| **L749 `_end_load_fade()`**，第一行、`visible = false` **之前** | `if _fade != null: _fade.visible = false` | `_fade_sink.call("end", 1.0)` |

**接线**：
```gdscript
screen.set_fade_sink(func(phase, a):
	match phase:
		"begin": AudioDirector.begin_load_fade()
		"tick":  AudioDirector.set_load_fade(a)
		"end":   AudioDirector.end_load_fade())
```

> ⚠ **已知边界（AUD-F7）**：最后一 tick 时 `m.tick()` 返回 `load_fade_end` → `_handle` → `_end_load_fade()` → `_fade.visible = false`，因此 `_set_alpha` / `"tick"` 那一块被跳过。音频侧收到的最后一个 `a` 可能是 0.97 左右（残留 −0.26 dB），所以 `end_load_fade()` **必须吸附**到 `0.0 dB`。吸附幅度 <0.3 dB，不可闻。

## 5.7 `PAUSED` 模式的触发方 —— ★ 当前**无人设置**

`time_controller.gd` L29 `var mode := "FLOWING"  # FLOWING | FOCUS | PAUSED` —— `PAUSED` **只存在于注释里**，全仓库没有任何代码设置它，也没有 `enter_paused()` / `exit_paused()`。

**后果**：若不补，`AudioDirector` 永远收不到"存档界面打开了"，§3 硬点 5 的 ducking 不会发生。

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| **(i) UI 直调** | 存档 / 暂停界面在 `open_screen()` 调 `AudioDirector.set_world_mode("PAUSED")`，关闭时调 `"FLOWING"` | 可行，但把时间语义分散到 L5 |
| **(ii) TimeController 补口（★ 推荐）** | 新增 `enter_paused()` / `exit_paused()`，复用**既有**信号 `time_scale_changed(old, 0.0, "PAUSED")` | **零新增事件** ✅；符合架构 §2「时间统一由 L2 时间控制器管理，玩法不得自管时间」；音频只需订阅一次就同时拿到 FOCUS 与 PAUSED |

**推荐 (ii)**，属 L2 变更，归工程侧裁量。若采 (ii)，`AudioDirector` 的唯一订阅即：

```gdscript
time_controller.time_scale_changed.connect(
	func(_old, _new, mode): set_world_mode(mode))
```

## 6.2 风险

| # | 风险 | 缓解 |
| --- | --- | --- |
| **AR-1** | **成功音的波峰因数预算只有 9.4 dB，偏紧。** 若制作时起音做得比 8 ms 更快，CF 会超预算 | §2.1.3 给了 attack **下限 5 ms**。若制作确需更锐的瞬态，二选一：TP 放宽到 −1.0 dBTP（Master 仍有 1 dB 余量），或 MaxM 降到 −19.0（但会挤压 AUD-H1 的 1.0 dB 余量，须同步下调失败音）。**任一改动须回写本文。** |
| **AR-2** | **AUD-S1（小扬声器存活）与「LPF 900 Hz = 闷的本体」在失败音上互相拉扯** | 已给 8 dB 的宽松阈（成功音 6 dB）。80 Hz 基频的谐波在 900 Hz LPF 下保留到 880 Hz，250–900 Hz 有充足内容，可达成。若实测不过，**优先加中频谐波密度，不要抬 LPF**——LPF 是"闷"的本体，动它就变成另一个音了。 |
| **AR-3** | **AUD-R1 阶梯可能被听成"声音坏了"** | 下限 −9 dB（仍清晰可闻）+ 600 ms 复位 + 视觉 `_hint` 常在。若 QA 反馈仍怪，先调 `UI_REPEAT_STEP_DB` 到 −1.5，不要取消阶梯。 |
| **AR-5**<br>（v1.1 新增） | ★ **真峰余量已被吃光。** designed v1 实测 TP = **−3.007 / −4.007 dBTP**，而 A5 的阈值恰为 −3.0 / −4.0 —— 余量只有 **0.007 dB**，等价于「刚好卡在天花板上」。资产显然是按**采样峰值** −3.0 / −4.0 dBFS 归一化的，但 A5 管的是**真峰**（4× 过采样），真峰恒 ≥ 采样峰值。**任何一次重新渲染、重采样、或加一层淡出窗，都可能把它推过线。** | ① 后续（尤其真实 Foley）资产**改按真峰归一化**，目标留 **≥0.3 dB** 余量（即 TP ≤ −3.3 / −4.3 dBTP）；② 归一化后**必须以 4× 过采样真峰复测**，不得只看采样峰值；③ 本条**不影响** designed v1 当前判定（仍是 pass），但**不要在此基础上再做任何增益类改动**。§1.5.4 的 CF 预算仍有空间（成功音 9.4 dB），代价是绝对响度，与 AR-1 是同一笔账。 |
| **AR-4** | **同帧读取（AUD-F3/F4）依赖工程侧严格照做**，一旦哪次重构把音频挪进 `_physics_process` 或自建 Tween，错位会悄悄回来，且很难在 CI 里发现 | 建议 E-10 的测试中加一条：断言 `AudioDirector` 内不存在 `Tween` 实例（`get_children()` 中无 `Tween`），把 AUD-F2 变成可断言项。 |
