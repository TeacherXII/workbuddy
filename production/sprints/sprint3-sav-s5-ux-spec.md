## 0. 支柱对齐与设计立场

| 支柱 | 本功能如何服务 | 反面（本文明令避免） |
| --- | --- | --- |
| **支柱三 · 自主掌控**（主） | 玩家 Own 自己的进度与节奏：何时冻结世界、回到哪一刻，由玩家决定 | 把存档做成「奖励/成就」感的庆祝反馈，会把「掌控」偷换成「被表扬」 |
| **支柱一 · 步步为营**（辅） | 手动槽是「计划性重来」的载体，与检查点的「失误性重来」互补 | 让手动槽和检查点槽长得一样 → 玩家分不清哪个是自己控制的 |
| **肃穆压迫（美术 §1 红线）** | 面板低调、无外发光、单声反馈、无音乐 sting | 任何亮闪、上行音程、和弦、粒子庆祝 |

**核心 UX 立场（三条，贯穿全文）**

1. **破坏性动作必须可预览、可撤回一步。** 覆盖 / 删除 / 读档都会丢失当前进度或槽内容 → 全部走模态确认，且确认弹窗必须**复述被影响对象**（哪个槽、什么时间戳），不能只说「确定吗？」。
2. **降低焦点密度优先于降低点击次数。** 4 行 × 3 动作 = 12 个焦点点是运动与认知负担（accessibility-matrix 行 14 Basic 档 = 仅预设键位可达、行 18 认知负荷）。故采用**行级焦点 + 固定按键动作条**，焦点点降到 4 个。
3. **禁用不等于沉默。** 对空槽按「读档」不应无反应——静默是认知负荷的来源。禁用动作按下时给「闷响 + 一行原因」，不给惩罚感。

## 1. UX 流程

### 1.1 屏幕清单与入口（扩展 `ux-spec.md` §1.3）

| 屏幕 ID | 状态 | 触发 | 是否阻断时间 | 说明 |
| --- | --- | --- | --- | --- |
| `SCR_PAUSE` | 既有 | `A10` Esc / Start | 阻断（PAUSED / T-03） | **新增 2 个菜单条目**（见下） |
| `SCR_SLOTS` | **新增** | `SCR_PAUSE` →「存档」或「读档」 | 阻断（继承 PAUSED） | 单一组件，`mode ∈ {SAVE, LOAD}`，两模式共用布局 |
| `SCR_CONFIRM` | **新增** | `SCR_SLOTS` 内破坏性动作 | 阻断 | 模态，`kind ∈ {OVERWRITE, LOAD, DELETE}` |
| `SCR_LOADFADE` | **新增（瞬态）** | 读档成功 | 阻断 → 释放 | 0.4s 淡入，结束回 `PLAYING` |

**`SCR_PAUSE` 菜单条目顺序（自上而下）**

```
继续
存档          ← 新增
读档          ← 新增
设置          （既有 → SCR_SETTINGS）
返回主菜单
```

- 「存档 / 读档」放在「设置」之上：它们是**进度动作**，与「继续」同族；「设置」是配置动作。分组降低扫视成本（认知负荷，矩阵行 18）。
- **不做**独立的「删除」菜单条目 —— 删除是槽的属性动作，不是全局动作。把它提到主菜单会抬高误触风险且增加一个焦点点。删除入口在 `SCR_SLOTS` 的动作条内（SAV-S5 AC 要求的「删除入口」由此满足）。

> **⚠️ 与 AC 字面的一处澄清（O-4）**：E11 SAV-S5 AC 写「暂停菜单有 存档/读档/删除 入口」。本规格把「删除」实现为 `SCR_SLOTS` 内的行级动作而非 `SCR_PAUSE` 的第三个菜单项，理由如上。若主理人要求字面对齐，改动很小（加一个菜单项，进入 `SCR_SLOTS` 的 `mode=DELETE`），但会多一个模式分支与一个焦点点，本文**不推荐**。

**状态定义表**

| 状态 | 输入 | 时长 | 退出条件 | 备注 |
| --- | --- | --- | --- | --- |
| `S0 BROWSING` | 全开 | — | A12 / A15 / A13 | 唯一可自由导航态 |
| `S1 CONFIRMING` | 仅弹窗内（焦点陷阱） | — | 确认 / 取消 | **默认焦点 = 取消**（破坏性动作的安全默认） |
| `S2 BUSY_WRITING` | **锁**（A13 排队不丢弃） | ≤3.0s | `save_completed` 或超时 | 显示「写入中…」，无进度条（异步写盘无法给真实进度，假进度条是欺骗） |
| `S3 BUSY_READING` | **锁** | ≤3.0s | `load_completed` 或超时 | 同上，文案「读取中…」 |
| `S4 RESULT_TOAST` | 全开（可继续导航） | 1.6s 自动消隐 | 计时 / 任意导航 | toast 不抢焦点；失败时行内标记**持久保留**，不随 toast 消失 |
| `S5 LOADING_FADE` | **锁** | 0.4s | 淡入完成 | 见 §3.3；结束发字幕（X-02） |

**为何 `S2/S3` 输入锁而非允许取消**：`write_slot` 是异步落盘且**没有取消 API**（Sprint 2 未提供）。给一个点了没用的「取消」按钮比不给更糟。Esc 在锁期间**排队不丢弃**，锁一解除立即执行 —— 玩家的意图被尊重，只是被延迟。

### 1.4 交互序列（逐动作步骤列表）

#### (a) 存档 · 空槽（最短路径，无确认）

1. `SCR_PAUSE` →「存档」→ `SCR_SLOTS(mode=SAVE)`，焦点默认落在**第一个可写行**（即第一个手动槽行，非检查点行）。
2. 玩家导航到空槽行 → 按 `A12`（Enter / A）。
3. **无二次确认**（空槽不破坏任何东西，加确认是纯摩擦）→ 直接 `S2 BUSY_WRITING`，调 `write_slot(id, snapshot)`。
4. 收到 `save_completed(id, true)` → `S4`：播成功「嗒」（§3.1）+ 行刷新为新时间戳 + toast「已存档 · 槽 {n}」+ 字幕（X-02）。
5. 1.6s 后 toast 消隐，回 `S0`，**焦点保持在同一行**（不跳转）。

#### (b) 存档 · 覆盖非空槽（AC 要求的二次确认）

1~2. 同上，玩家选中**非空**槽行按 `A12`。
3. → `S1 CONFIRMING(kind=OVERWRITE)`，弹窗文案：

   > **覆盖存档？**
   > 槽 2 现存：`2026-03-25 14:07 · #ch_gatehouse_01`
   > 覆盖后该记录将无法找回。
   > 　　〔取消〕（默认焦点）　〔覆盖〕

   - **必须复述被覆盖对象的时间戳与检查点 id** —— 这是玩家判断「这个槽能不能扔」的唯一依据。
4. 选〔覆盖〕→ `S2`，其余同 (a) 步骤 4–5。选〔取消〕→ 回 `S0`，焦点回到原行。

#### (c) 读档

1. `SCR_PAUSE` →「读档」→ `SCR_SLOTS(mode=LOAD)`，焦点默认落在**最近一次写入的非空、非损坏行**（时间戳最大者）。若全为空 → 落在第一行并显示空态引导（§1.5）。
2. 玩家选中非空行按 `A12` → **总是**进入 `S1 CONFIRMING(kind=LOAD)`（读档会丢弃当前未存进度，永远是破坏性的）：

   > **读取存档？**
   > 将回到 `2026-03-25 14:07 · #ch_gatehouse_01`。
   > 当前未存进度将丢失。
   > 　　〔取消〕（默认焦点）　〔读取〕

3. 确认 → `S3 BUSY_READING`，调 `read_slot(id)`。
4. `load_completed(id, true)` → `S5 LOADING_FADE`：世界 0.4s 淡入（§3.3）+ 音频床同步 0.4s 升起 + 完成瞬间发字幕「已读取存档 · 槽 {n}」（X-02，说话者 =「系统」）。
5. 淡入结束 → 释放输入 → `PLAYING`。UI 全部卸载（不残留暂停面板）。
6. `load_completed(id, false)` → `S4` 失败分支：闷响 + ⚠ + toast「存档版本不匹配」或「存档已损坏」+ **该行永久标记为损坏态**（`⊘` 缩略 + 〔⚠ 损坏〕徽标），且该行的「读档」动作转为禁用。

#### (d) 删除

1. `S0` 中选中**非空**行 → 按 `A15`（Del / Y）。
2. → `S1 CONFIRMING(kind=DELETE)`：

   > **删除存档？**
   > 槽 2：`2026-03-25 14:07 · #ch_gatehouse_01`
   > 　　〔取消〕（默认焦点）　〔删除〕

3. 确认 → 删除槽文件 → 行立即转为空态 → 播**成功「嗒」**（删除成功也是「操作成立」，用同一个成立音；不为删除单造一个音，避免音效通胀）。
4. **焦点保持在同 index 的行**（现为空槽），不跳到列表首（EC-10）。
5. 损坏槽**允许删除**（这是玩家清理损坏档的唯一手段，必须保留）。

#### (e) 返回

- `A13`（Esc / B）在 `S0` → 回 `SCR_PAUSE`，焦点落回来时的那个菜单项（「存档」或「读档」）。
- `A13` 在 `S1` → 等价〔取消〕。
- `A13` 在 `S2/S3` → 排队，锁解除后执行。

### 1.5 空状态 / 错误状态 / 忙状态

| 态 | 触发 | 视觉 | 文案 | 可用动作 |
| --- | --- | --- | --- | --- |
| **空槽** | 该 id 无文件 | 缩略占位显 `──`；主行「槽 N」；副行「— 空槽位 —」（`#DCE3EC` @70%） | — | SAVE 模式：可存 ✅ ｜ LOAD 模式：读档**禁用** ｜ 删除**禁用** |
| **全空（LOAD 模式）** | 3 槽皆空 | 列表照常显示 3 个空行 | 面板底部加一行引导：「尚无手动存档。可在暂停菜单选择『存档』写入。」 | 仅〔返回〕 |
| **损坏 / 版本不匹配** | `load_completed(id,false)` 或列表构建时读版本失败 | 缩略占位显 `⊘`；徽标〔⚠ 损坏〕`#D64545` 边 + 实心三角 `!` + 2.0Hz 双拍脉冲 | 副行改为「存档版本不匹配」/「存档已损坏」 | 读档**禁用**；**覆盖可用**（覆盖是清理手段）；删除**可用** |

## 3. 音频草图

> **性质**：设计草图，给音频侧的**约束与意图**，不是最终资产参数。终稿归音频指导。
> **总纲（继承 GDD §5「Sensation 克制」+ art-bible §1 肃穆压迫）**：反馈走**质地**不走**烟花**。全部为**单声、无音高旋律、无和弦、无混响拖尾、无音乐 sting**。任何「上行音程」= 庆祝感 = 破支柱与美术红线，**禁止**。

### 3.1 存档成功 —— 单声低音「嗒」

| 参数 | 规格 | 理由 |
| --- | --- | --- |
| 音色意象 | 石室内一枚小石子落在石板上 / 厚木闩合位 —— **一次敲击，一个瞬态** | 与 `ux-spec.md` §2.2 足音 foley「咔/嗒」同族，near-diegetic 而非 UI 电子音 |
| 基频 | **110–140 Hz**（A2–C#3） | GDD §5 明写「低音」；低于足音（避免与玩法音混淆） |
| 时长 | **90–140 ms** | 短到「事件成立」，不到「值得庆祝」 |
| 包络 | Attack ≤ **8 ms** · Decay **80–120 ms** · **无 Sustain** · Release 折入 Decay | 纯瞬态；有 sustain 就变成「音」而不是「响」 |
| 滤波 | LPF ≈ **2.2 kHz**（去掉「叮」的明亮泛音）· HPF ≈ **60 Hz**（防浑浊） | 「嗒」不是「叮」；明亮高频 = 电子确认音 = 破基调 |
| 响度 | **−18 LUFS-M**，True Peak ≤ **−6 dBTP**；比足音 foley 低 **2–3 dB** | UI 音永不盖过世界音（世界内优先，art §8.1） |
| 声像 / 空间 | **单声道居中**；混响 RT60 ≤ **0.25 s**（贴石室，不是大厅） | 居中 = 系统音，与世界方位音区分 |
| 复用 | **删除成功复用同一音**（音量 −1 dB） | 「操作成立」是同一语义；为删除单造音效会造成音效通胀 |
| 禁止 | 上行音程 / 和弦 / >1 个音符 / 铃铛 / 金属亮片 / 任何 >3 kHz 的闪亮层 | 全部指向「庆祝」，与支柱三的「掌控」相悖 |

### 3.2 存档 / 读档失败 —— 闷响 + ⚠

| 参数 | 规格 | 理由 |
| --- | --- | --- |
| 音色意象 | 厚门顶到门框未合上 / 石板下沉一寸卡住 —— **动作没走完** | 表达「未成立」而非「你错了」；不制造惩罚感 |
| 基频 | **70–90 Hz** | 明显低于成功音，靠**音高方向**（下）编码否定 |
| 时长 | **180–260 ms**（长于成功音） | 「拖住」的感觉 = 未完成 |
| 包络 | Attack ≤ **12 ms** · Decay **170–250 ms** | 略软的起音 = 闷 |
| 滤波 | LPF ≈ **900 Hz** ← **这一项就是「闷」的本体** · HPF ≈ 45 Hz | 无高频 = 闷 |
| 音高包络 | 120 ms 内 **下滑 2 个半音** | 下行 = 否定，跨文化稳健，不依赖语言 |
| 响度 | **−18 LUFS-M**（与成功音同档，**绝不更响**），TP ≤ −6 dBTP | ★ 失败音比成功音响 = 惊吓 + 惩罚感，对听觉敏感 / 认知障碍玩家不友好 |
| **配套视觉（强制三重编码 C-05/C-07）** | `#DCE3EC` 白载体文案 + `#D64545` 边框 + **实心三角 `!`** + **2.0Hz 双拍脉冲**（V-01 ✅） | 音频不可作唯一通道（听障玩家）；视觉不可单靠颜色（色盲玩家） |
| **配套字幕（X-02）** | 说话者「系统」+ ♪ 图标 + 具体原因文案 | 见 §2.2 字幕表 |
| 复用 | **禁用动作被按下**时复用同一音（−3 dB） | 「你按的这个动作不成立」是同一语义 |

### 3.3 读档 0.4 s 淡入（视听同步）

| 通道 | 规格 |
| --- | --- |
| **时间轴** | `t=0` 触发（`load_completed(id,true)` 到达）→ `t=0.4s` 完成 |
| **视觉** | 全屏 alpha 0 → 1，**ease-out**（V-06 禁硬切）；`SCR_SLOTS` / scrim 在 `t=0` 瞬间卸载（不参与淡入，避免 UI 幽灵） |
| **音频（环境床）** | Ambience bus 从 −∞ 沿**同一条 ease-out 曲线**升至标定值，**0.4 s**，与视觉共用同一个 tween 驱动 —— 视听必须同源，否则会出现「先听到后看到」的错位感 |
| **音频（UI bus）** | 这 0.4 s 内 **静默**。**不叠加读档成功「嗒」** —— 世界重新出现本身就是最强的成功反馈；再叠 UI 音会变成两个「成立」信号 |
| **玩法音** | 足音 / 声波环等在 `t=0.4s` 后才允许触发（避免淡入中出现全音量玩法音） |
| **字幕（X-02）** | 在 **`t=0.4s`（淡入完成）** 发出「已读取存档 · 槽 {n}」，**不在 `t=0` 发** —— 淡入中屏幕还是黑的，字幕会孤零零悬空 |
| **V-01 / V-06** | 单次 ease，非周期性亮灭 ✅ |
